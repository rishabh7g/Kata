## Smell notes — m05-e2 (construct: Error Design)

**Where the temptation lives.** The stub itself is clean; the Smell is the standard library's own habits. The obvious building blocks all throw on exactly the cases this Target Interface defines as normal: `Queue<string>.Dequeue()` throws on empty (so `PlayNext` tempts a try/catch or a pre-check that returns a throw path), a `Dictionary` indexer throws on missing (so a lookup-based `Drop` tempts `KeyNotFoundException`), and a duplicate-add tempts an `ArgumentException` or an `InvalidOperationException("already queued")`. An implementer following those instincts ships an API where every caller needs catch blocks.

**What the Test Suite pins down.** Every edge the interface defines out of existence has a test asserting the *defined* behavior, not an exception: `PlayNext` on empty returns `""` (repeatedly, and again after the last track plays); `Drop` of a never-queued track, on an empty queue, and twice in a row are all successful no-ops; re-queuing a waiting track moves it to the end without duplicating, while re-queuing an already-played track is a fresh add. FIFO order, removal-on-play, and `Length` are pinned so the no-throw behavior can't be faked by doing nothing. The final test (`NoSequenceOfCalls_EverThrows`) runs one mixed sequence through every edge under `Record.Exception` and asserts null — the headline claim of the exercise stated as a single assertion.

**What a good solution hides.** A single `List<string>` (or `LinkedList<string>`) is enough: `List.Remove` already returns `bool` instead of throwing, so `Drop` is one call and re-queue is `Remove` + `Add`; `PlayNext` is a count check returning `""` before taking index 0. The insight to look for in review: the clean solution has **zero** `throw`, `try`, or `catch` anywhere — errors weren't handled, they were designed out. Tests were written from the Target Interface only; the stub contains no behavior to copy.

**Notes for the reviewer.** Tests deliberately avoid `null`/`""` as track names — the contract reserves `""` as silence and doesn't define them, so testing them would invent contract. Stub is ~15 non-blank lines, well inside the 200-line budget for the learner's implementation.
